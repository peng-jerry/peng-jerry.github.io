Noteable

15-113

HW 5

Skills: React, Vite, Python, Flask, SQLAlchemy, PostgreSQL, JWT authentication, REST API design, testing, Render, Neon & GitHub Pages deployment

A full-stack note-taking app: sign up, write notes in Markdown with a live preview, and organise them into folders inside folders. Every account’s notes are private to it, everything saves automatically as you type, and the layout adapts from a three-pane desktop view down to a phone.

Open Noteable

Create a free account to try it — the first request after a quiet spell can take up to a minute while the free-tier server wakes up

Three Deployed Pieces

The frontend is a React single-page app built with Vite, and the built copy is served straight from this site at /noteable/. It talks to a Flask REST API hosted on Render, which stores everything in a PostgreSQL database on Neon. Database migrations (Alembic) run automatically on every deploy. The app uses hash URLs (/noteable/#/notes/…) on purpose: GitHub Pages only knows this site’s own 404 page, so ordinary deep links would break as soon as someone refreshed.

Accounts and Private Routes

Logging in returns a short-lived access token and a longer-lived refresh token. When an access token expires, the frontend quietly swaps the refresh token for a new one and retries the request; if several requests expire at once, they share a single refresh. Logging out revokes both tokens on the server, and changing your password invalidates every older session. On the frontend, routes are split into public (the landing page), public-only (login and register) and private (your notes and settings). Visiting a private page while logged out sends you to the login page, then back to where you were going. On the backend, every query is scoped to the signed-in user, and someone else’s note returns the same 404 as a note that doesn’t exist, so IDs can’t be probed.

Folders Inside Folders

Folders form a tree through a single parent_id column. The API rejects moves that would put a folder inside itself or one of its own subfolders, caps nesting at ten levels, and keeps sibling names unique. Deleting a folder cascades to everything inside it, and the confirmation dialog tells you exactly how many subfolders and notes will go with it before you commit.

Autosave Without Lost Edits

There’s no save button. Edits are sent about a second after you stop typing, and only the fields that changed are sent. Saves never overlap: anything typed while one is in flight is merged and sent next, so they can’t arrive out of order and overwrite newer text with older text. A failed save keeps your changes and offers a retry, switching notes saves whatever is pending first, and the browser warns you before closing a tab with unsaved work.

Built to Grow

Noteable is meant to be the first piece of a larger site, so the backend isn’t notes-specific at its core. Every feature is its own Flask blueprint under a versioned /api/v1 prefix, user accounts are shared rather than tied to notes, and every error — validation, authentication, database outages — comes back in the same JSON shape with a stable error code. Adding a new section later means adding a package, not rewriting this one.

Testing, and the Bugs It Caught

The backend has 39 pytest tests, run against both SQLite and a real PostgreSQL server, and the frontend has 32 Vitest tests. On top of that, a scripted headless-browser run clicks through the whole app against the real API at desktop, tablet and phone sizes. That run caught bugs the unit tests couldn’t: deleting the folder you were viewing left the app stuck on a folder that no longer existed, and the search box trimmed spaces while you were still typing. Deployment caught two more. Render had been running its default start command instead of the project’s, and the service URL turned out not to be the one the frontend expected — the default name was already taken by someone else’s service. Checking that the health endpoint reported this API (and a working database) before building is what caught it.
